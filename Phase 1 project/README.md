## Overview

This project uses **Terraform** to provision AWS infrastructure and **Ansible** to configure the servers it creates.

The flow is simple:

```
Terraform creates the servers  ->  Ansible configures the servers
```

Terraform builds a VPC, a public subnet, an Internet Gateway, a route table, two security groups, and two EC2 instances. Ansible then connects from one instance (the **control node**) to the other (the **managed node**), updates it, installs Docker, starts Docker, and proves it works by running a test container.

## Architecture

```
                         Internet
                             |
                     Internet Gateway
                             |
          +------------------ VPC (172.20.0.0/16) ------------------+
          |                                                       |
          |        Public Subnet (172.20.1.0/24)                    |
          |                                                       |
          |   +----------------+   SSH (22)   +----------------+  |
          |   |  Control Node  | -----------> |  Managed Node  |  |
          |   |  Ansible lives |   private    |  Docker gets   |  |
          |   |  here          |   network    |  installed     |  |
          |   +----------------+              +----------------+  |
          |        ^                                              |
          +--------|----------------------------------------------+
                   |
             SSH from my IP only
```

### Why two nodes

In real environments, the machine that runs automation is kept separate from the machines it manages. The **control node** holds Ansible and the SSH key. The **managed node** is the target server and needs nothing installed beforehand except SSH.

### Security design

| Security group | Allows | From |
|---|---|---|
| `control-node-sg` | SSH (port 22) | My own IP address only (`/32`) |
| `managed-node-sg` | SSH (port 22) | The control node's security group only |

The managed node cannot be reached over SSH from the open internet or even from my laptop. The only way in is through the control node.

## Terraform Resources

| Resource | Purpose |
|---|---|
| `aws_vpc` | The isolated network everything lives in |
| `aws_subnet` | A public subnet inside the VPC, with public IPs assigned on launch |
| `aws_internet_gateway` | The door between the VPC and the internet |
| `aws_route_table` and association | Sends outbound traffic to the Internet Gateway |
| `aws_security_group` (x2) | Controls who can reach each node |
| `aws_instance` (x2) | The control node and the managed node (Ubuntu 22.04) |
| `data.aws_ami` | Looks up the latest official Ubuntu 22.04 image automatically |
| `local_file` | Writes the Ansible inventory file using the real managed node IP |

### Terraform variables

| Variable | Description | Default |
|---|---|---|
| `aws_region` | AWS region to deploy into | `eu-west-1` |
| `vpc_cidr` | CIDR block for the VPC | `172.20.0.0/16` |
| `subnet_cidr` | CIDR block for the public subnet | `172.20.1.0/24` |
| `instance_type` | EC2 instance type for both nodes | `c7i-flex.large` |
| `key_name` | Name of an existing AWS key pair | none (required) |
| `allowed_ssh_cidr` | My IP in CIDR form, allowed to SSH into the control node | none (required) |

## Ansible Playbook

The playbook (`playbook.yml`) targets the `managed_nodes` group and runs with `become: true` (sudo). It performs these tasks:

1. Update the apt package index
2. Upgrade installed packages
3. Install Docker prerequisites (`ca-certificates`, `curl`, `gnupg`)
4. Add Docker's official GPG key and apt repository
5. Install Docker Engine (`docker-ce`, `docker-ce-cli`, `containerd.io`, `docker-compose-plugin`)
6. Start and enable the Docker service
7. Add the `ubuntu` user to the `docker` group
8. Run `docker run hello-world` to test the installation and print the output

The playbook is idempotent, so running it more than once leaves the server in the same final state.

## How I Ran It

### 1. Provisioned the infrastructure (from my local machine, WSL Ubuntu)

```bash
cd terraform
terraform init
terraform plan
terraform apply
```

Created `terraform.tfvars` first with my own values:

```hcl
key_name         = "<my-aws-key-pair-name>"
allowed_ssh_cidr = "<my-public-ip>/32"
```

### 2. Copied the key and the Ansible files to the control node

```bash
chmod 400 ~/.ssh/<key-name>.pem
scp -i ~/.ssh/<key-name>.pem ~/.ssh/<key-name>.pem ubuntu@<control-node-public-ip>:~/.ssh/
scp -i ~/.ssh/<key-name>.pem -r Ansible ubuntu@<control-node-public-ip>:~/
```

### 3. Prepared the control node

```bash
ssh -i ~/.ssh/<key-name>.pem ubuntu@<control-node-public-ip>
chmod 400 ~/.ssh/<key-name>.pem
chmod 755 ~/Ansible && chmod 644 ~/Ansible/*
sudo apt update && sudo apt install -y ansible
```

### 4. Tested connectivity, then run the playbook

```bash
cd ~/Ansible
ansible managed_nodes -m ping
ansible-playbook playbook.yml
```

### 5. Cleaned up when finished

```bash
terraform destroy
```

## Challenges and What I Learned

- **SSH key permissions:** SSH refuses to use a private key that other users can read. `chmod 400` on the `.pem` file fixed the "unprotected private key file" error. Running the commands from WSL Ubuntu instead of PowerShell made permissions behave correctly.
- **Connection timeout versus permission denied:** A timeout meant the connection never reached the server, which pointed to the security group. My public IP had changed, so the `allowed_ssh_cidr` value was outdated. Permission denied meant a key or username problem instead.
- **Ansible ignoring `ansible.cfg`:** Copying the folder from a Windows drive gave it open (world-writable) permissions, and Ansible refuses to load a config from such a directory. Setting the folder to `755` and the files to `644` fixed it.
- **Hardcoded IPs:** Terraform now writes the Ansible inventory file itself with the managed node's real private IP, so there is no manual copying of addresses.
- **Cost control:** Stopping instances between sessions avoids paying for compute while keeping the setup intact.

- `.gitignore` excludes `*.pem`, `terraform.tfvars`, `*.tfstate`, `*.tfstate.backup`, and the `.terraform/` directory.
